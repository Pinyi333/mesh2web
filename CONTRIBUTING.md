# Contributing to mesh2web

Thanks for helping! mesh2web is plain ES modules with JSDoc types: no TypeScript
compile step, no frontend framework.

## Setup

```bash
npm install
npm run assets   # CC0 procedural test models in test-assets/
npm run build    # element bundle + Studio worker core + docs vendor files
npm test
npm run dev      # http://127.0.0.1:5173/apps/docs/ · /apps/studio/ · /examples/basic/
```

Browser smoke tests use `playwright-core`. Install a browser once with
`npx playwright-core install chromium`, or point `MESH2WEB_CHROMIUM` at an
existing Chromium, then run `npm run test:e2e`.

## Layout

```
packages/core       pipeline (inspect, clean, simplify, compress, report): Node + browser
packages/cli        `mesh2web` command
packages/element    <web-model> Web Component (+ gsap bridge)
packages/presets    optimization + lighting presets (JSON)
apps/docs           website (GitHub Pages root)
apps/studio         in-browser GUI (/studio)
examples/           standalone HTML examples
scripts/            build, dev server, test assets, e2e, lint
```

## Guidelines

- **Small PRs**: one feature or fix each, with a test when behavior changes.
- **Keep the element shell small**: `npm run build` fails if `web-model.js` exceeds 15 KB gzip. Anything three.js-related belongs in `viewer.js`, which is loaded lazily.
- **No frameworks** in the runtime, docs or Studio. GSAP is optional and always a peer.
- **Accessibility**: respect `prefers-reduced-motion`, keep keyboard access, and show the poster as the fallback.
- **Test assets** must be generated by code or CC0. Never commit models with unclear licenses.
- Commit messages: imperative mood (`Add neon preset rim light`).

## Good first issues

- A new lighting or optimization preset (`packages/presets/src/*.json`)
- Translations of the docs site or README
- Another example in `examples/`

## Releasing (maintainers)

All packages are published under the `@mesh2web` npm scope. Scoped packages are
private by default and the free npm plan cannot publish private packages, so
every package's `package.json` sets:

```json
"publishConfig": { "access": "public" }
```

With that in place a plain `npm publish` works. For the very first publish you
can also be explicit:

```bash
npm run build && npm test
npm publish --workspaces --access public
```

Or create a GitHub Release: `.github/workflows/release.yml` publishes all
workspaces with provenance, using the `NPM_TOKEN` repository secret.

Bump versions in every `packages/*/package.json` together, including internal
dependency ranges such as `"@mesh2web/core": "0.1.0"`, and add an entry to
`CHANGELOG.md`.
